# 关闭 HBM 前缀缓存的 SSD 容量扫描

本实验比较固定 **2 GiB DRAM** 下四种策略的 SSD 写入量和首 token 延迟。模型为 Qwen2.5-1.5B-Instruct，使用 part1 轨迹、300 会话、100 倍回放、并发 8、随机种子 7。DRAM 淘汰水位为 0.75，`gpu-memory-utilization=0.20`，各组实测 GPU KV 容量均为 115,440 tokens。四档 SSD 容量各运行四种策略，另运行一次 0 GiB 的 L1-only 对照。每组完成 5,950 个请求，零错误、零跳过。[实验配置](settings.txt)

Gandalf 在 2、8 和 16 GiB 三档写入量最低。4 GiB 下，LRU 写回的写入量最低。L1-only 的客户端 TTFT 均值和 P90 都低于本轮有 SSD 的组。这轮负载下，L2 减少的 GPU prefill 时间小于缓存查询和加载增加的等待。该结论针对首 token 延迟。L1-only 的平均整请求耗时为 532.15 ms，长于 2 GiB Bidaw 的 513.98 ms。[完整数据](sweep_summary.json) · [原始汇总](sweep_summary.txt)
