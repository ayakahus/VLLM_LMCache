# 并发 64 的 SSD 容量扫描

客户端并发和 vLLM 最大并发均设为 64。沿用并发 8 那轮的 Qwen2.5-1.5B-Instruct、part1 轨迹、300 会话、100 倍回放和随机种子 7。HBM 前缀缓存关闭，DRAM 为 2 GiB，淘汰水位为 0.75，prompt 上限为 3,800 tokens，上下文上限为 4,096 tokens。vLLM 的 `gpu-memory-utilization` 仍为 0.20，并显式固定 7,215 个 GPU KV 块，实测容量为 115,440 tokens。[本轮配置](settings.txt) · [并发 8 报告](../../gandalf_full_part1_nohbm_300_l1_2_ssd_sweep/sweep.5kk8wmg4/sweep_report.md)

四档 SSD 各运行四种策略，L1-only 独立运行一次。17 组均完成 5,950 个请求，零错误、零跳过。各组的回放调度和实际 prompt 指纹均与并发 8 那轮一致。
