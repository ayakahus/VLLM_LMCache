# 逐请求 TTFT 分解与 lookup 排查

Qwen2.5-1.5B-Instruct，part1 轨迹，300 会话，每组 5,950 个请求。以 100 倍速回放，并发 8，开启 HBM 前缀缓存。GPU KV 容量为 115,440 tokens，DRAM 为 5 GiB，SSD 为 10 GiB，淘汰水位为 0.75。[运行配置](cache_settings.txt) · [原始汇总](ttft_breakdown.txt)

## LRU 逐请求分解

通过回放会话与轮次关联 `round_id`，再关联 vLLM 调度和 LMCache 事件。每个阶段使用相邻时间戳之差。在 lookup 和异步加载窗口内，分别对可配对的 SSD 读盘和 GPU 拷贝区间去重后计时。客户端 TTFT 减去入队到首次 prefill 调度的耗时，得到未归因时间。该项包含入队前的处理，以及首次调度后的 prefill、首 token 生成与返回，现有时间戳无法在单请求层面进一步拆分。

所有阶段均用全部 5,950 个请求计算均值和 P90，未经过的阶段计 0。校验了每个请求的阶段和与实测客户端 TTFT 一致。均值可以相加，总 TTFT 的 P90 从完整请求耗时独立计算。

| 阶段 | 平均（ms） | P90（ms） |
| --- | ---: | ---: |
| 入队 → 开始 lookup | 0.3775 | 0.6544 |
| Lookup（无可单独计时的 SSD 读盘） | 8.1964 | 23.2024 |
| Lookup 开始 → SSD 读盘开始 | 5.8124 | 17.8844 |
| SSD → DRAM 读盘 | 9.3378 | 29.8144 |
| SSD 读盘完成 → lookup 确认 | 5.8007 | 20.3698 |
| Lookup 确认 → 开始异步加载 | 0.1290 | 0.2877 |
| 异步加载（拷贝时间戳未能对齐） | 0.0566 | 0.0000 |
| 异步加载开始 → GPU 拷贝开始 | 5.9286 | 19.6864 |
| DRAM → GPU 拷贝 | 9.1914 | 19.0763 |
| GPU 拷贝结束 → 加载确认 | 8.2163 | 23.2544 |
| 缓存就绪 → 首次 prefill 调度 | 0.4292 | 0.7337 |
| 未归因时间（入队前及首次调度后） | 50.3129 | 66.4211 |
| **客户端 TTFT** | **103.7888** | **167.7591** |

LRU 有 2,325 个请求可单独计时 SSD 读盘，3,622 个可单独计时 GPU 拷贝。另有 10 个请求的 GPU 拷贝事件未落在异步加载窗口内，保留完整的加载窗口作为一段。

## 与 Bidaw、Gandalf 的阶段对比

| 逐请求均值（ms） | LRU | Bidaw | Gandalf |
| --- | ---: | ---: | ---: |
| Lookup 等待（含 SSD 读盘） | 29.147 | 50.774 | 112.141 |
| 异步 KV 加载（含 DRAM → GPU 拷贝） | 23.393 | 26.343 | 87.144 |
| 其余调度间隔 | 0.936 | 0.984 | 1.024 |
| 未归因时间 | 50.313 | 50.888 | 54.084 |
| **客户端 TTFT** | **103.789** | **128.990** | **254.393** |

Bidaw 比 LRU 多 25.20 ms，其中 21.63 ms 出在 lookup。SSD 读盘从 9.34 增到 19.97 ms/请求。Gandalf 比 LRU 多 150.60 ms，其中 lookup 多 82.99 ms，异步加载多 63.75 ms。Gandalf 的 SSD 读盘均摊仅 2.68 ms/请求。对只回传一个 KV 块的操作，Gandalf 的实测拷贝均值是 38.98 ms，LRU 是 11.40 ms。[延迟汇总](ttft_breakdown.txt)

## Lookup 等待在哪一段

下表仅包含每轮只有一个可配对的 LMCache 预取请求、存在命中事件，且服务端预取提交和最后一个命中事件都落在 vLLM lookup 窗口内的样本。第一段包含提交、接收及到达预取入口前的服务端工作。最后一段包含结果交付与调度器确认，现有打点无法细分。

| 策略与命中层 | 请求数 | 发起 → 提交预取（ms） | 提交 → 记录命中（ms） | 记录命中 → vLLM 确认（ms） | Lookup 合计（ms） |
| --- | ---: | ---: | ---: | ---: | ---: |
| LRU，有 SSD 命中 | 2,325 | 2.94 | 37.39 | 13.29 | 53.62 |
| Bidaw，有 SSD 命中 | 2,733 | 5.43 | 69.65 | 16.60 | 91.68 |
| LRU，仅 DRAM 命中 | 1,299 | 2.63 | 4.39 | 10.59 | 17.62 |
| Gandalf，仅 DRAM 命中 | 3,283 | 51.46 | 59.17 | 41.12 | 151.75 |

有 SSD 命中的请求中，Bidaw 比 LRU 多出的 38.06 ms 里，约 32 ms 落在预取提交到记录命中之间。该区间含排队和读盘，未单独测得 disk-HRRN 并发门控增加的等待。[Bidaw 派发实现](../../../bidaw/dual_queue_scheduler.py#L193)

Gandalf 的纯 DRAM 命中请求中，3,000 个在淘汰周期内提交预取，平均 lookup 为 163.92 ms。周期外 283 个请求平均为 22.76 ms。Gandalf 的淘汰周期平均 23.24 秒，其中重复选块累计占 17.85 秒。结果显示淘汰与 lookup 延迟高度相关，尚未定位到具体的锁或线程。[Gandalf 淘汰循环](../../../bidaw/gandalf_runtime.py#L388) · [后台统计](ttft_breakdown.txt)
